## 部署方案对比

| 方案 | 适用场景 | 复杂度 | 稳定性 | 企业级特性 |
|------|----------|--------|--------|-----------|
| **Docker 部署** ⭐ | 生产环境 | 低 | 高 | 容器化、编排、监控 |
| **本地进程** | 开发测试 | 中 | 中 | 简单快速 |
| **应用层 Fallback** | 嵌入式部署 | 低 | 高 | 轻量级、无依赖 |

## 推荐部署方案：Docker + LiteLLM

### 1. 环境准备

```bash
# 安装 Docker（如未安装）
# Ubuntu/Debian
curl -fsSL https://get.docker.com | sh

# 或手动安装
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh
```

### 2. 一键启动（推荐）

```bash
# 进入项目目录
cd /home/oy0/security-agent

# 启动 LiteLLM 代理（自动使用 Docker）
bash scripts/litellm.sh start

# 输出示例：
# [LiteLLM] ✓ 检测到 Docker，使用容器化部署
# [LiteLLM-Docker] 正在启动 LiteLLM 容器...
# [LiteLLM-Docker] ✅ LiteLLM 容器已启动
# [LiteLLM-Docker] 代理地址: http://localhost:4000/v1
```

### 3. 启用代理模式

```bash
# 修改 .env 启用 LiteLLM
bash scripts/litellm.sh enable

# 重启应用
bash boot_stop.sh && bash boot_start.sh
```

### 4. 验证部署

```bash
# 查看状态
bash scripts/litellm.sh status

# 输出示例：
# ✅ LiteLLM 容器运行中
# NAMES                    STATUS              PORTS
# security-agent-litellm   Up 2 minutes        0.0.0.0:4000->4000/tcp
# ✓ 服务健康
```

## 架构优势说明

### 1. 高可用设计

```yaml
# litellm_config.yaml
fallbacks:
  - mimo-chat:
      - deepseek-chat    # 自动回退
```

**故障场景**：
- MiMo 服务超时 → 自动切换到 DeepSeek
- 切换时间 < 2 秒
- 用户无感知

### 2. 成本监控

```python
# 自动统计各模型调用成本
cost_summary = {
    "mimo-v2.5-pro": {"calls": 100, "cost_cny": 1.5},
    "deepseek-chat": {"calls": 20, "cost_cny": 0.3},
}
```

**企业价值**：
- 成本透明化
- 预算控制
- ROI 分析

### 3. 审计日志

```
logs/litellm.log
├── 请求时间
├── 用户标识
├── 调用模型
├── Token 消耗
├── 响应时间
└── 是否触发 fallback
```

**合规要求**：
- 操作可追溯
- 安全审计
- 故障排查
