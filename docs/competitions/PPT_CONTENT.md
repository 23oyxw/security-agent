## P6 · 三层安全防御（60秒）⭐ 核心页

**标题**：安全校验 — 让 AI 不能乱来

**三层流程图**：

```
用户输入命令
    ↓
┌─ 第1层：静态风险评估 (30%) ────────┐
│  规则引擎 · 注入扫描 · 四级风险矩阵  │
│  rm -rf / → 直接识别 → CRITICAL     │
└────────────────────────────────────┘
    ↓
┌─ 第2层：动态意图审计 (35%) ────────┐
│  用户意图 vs 拟执行命令 · 交叉校验   │
│  "清理临时文件" → rm -rf → 意图偏离  │
└────────────────────────────────────┘
    ↓
┌─ 第3层：受限执行环境 (35%) ────────┐
│  最小权限 · 沙箱隔离 · 备份回滚      │
│  OverlayFS COW · PrivilegeBroker    │
└────────────────────────────────────┘
    ↓
裁定：ALLOW / CONFIRM / APPROVE / ESCALATE / DENY
```

**实测数据**：

- `rm -rf /tmp/test` → **deny**（注入阻断）
- `ls -la /tmp` → **allow** (93.25分)

## P7 · 7层沙箱隔离（30秒）

**标题**：写得进去，回得来

**七层递进图**：

```
setuid 降权 → rlimit 资源限制 → OverlayFS 写时复制
→ mount_ns 文件隔离 → net_ns 网络隔离
→ seccomp 系统调用过滤 → cgroup 资源管控
```

**关键数字**：

- 12 个安全探针（权限×4 + 文件系统×4 + 网络×4）
- 7 种变异策略 Fuzzer（路径遍历、命令注入、Unicode绕过……）
- CRITICAL 级操作直接拒绝自动执行

```

```

## P11 · 根因分析（30秒）

**标题**：不仅发现问题，更要找到原因

**6 维检测引擎**：

| 维度 | 检测项 | 示例 |
|------|--------|------|
| CPU | 负载过高 | load > CPU核数×2 → 定位高CPU进程 |
| 内存 | OOM 事件 | 日志检测 OOM Killer → 定位内存大户 |
| 磁盘 | 空间不足 | use% > 85% → 大文件排查 |
| 进程 | 异常进程 | CPU > 90% 单进程 → 检查是否为恶意 |
| 网络 | 可疑端口 | 非标准端口监听 → 确认服务合法性 |
| 日志 | 错误爆发 | 30分钟 > 10条错误 → 根因定位 |

**关联引擎**：6 条因果链规则（如 内存不足 → OOM → 进程被 kill）
