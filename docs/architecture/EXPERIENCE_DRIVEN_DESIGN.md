## 设计原则

| # | 原则 | 一句话 | 反例（当前存在的问题） |
|---|------|--------|------------------------|
| 1 | **不打扰** | 能自动处理的绝不告警，能告警的绝不中断 | 每个监控事件都写 alerts.log，产生噪音 |
| 2 | **可解释** | 每个决策都要能回答「为什么」 | 三层防御评分 93.3 分，但不知道为什么扣了 6.7 分 |
| 3 | **可追溯** | 任何操作都有完整的「前→中→后」快照 | 终端执行完只返回 stdout/stderr，不知道改了哪些文件 |
| 4 | **渐进式** | 新用户 5 分钟上手，老用户能深挖 | 30 条 Playbook 堆在一个文件里，没人能找到想要的 |
| 5 | **自愈优先** | 系统先尝试自己修，实在不行再找人 | 磁盘满了只告警，不会自动清理日志 |

## 一、全域沙箱 — 体验设计

### 1.1 目标体验

> 用户输入一条可能有风险的操作 → 系统在后台隔离执行 → 返回结果时附带「我做了什么保护 + 文件发生了什么变化」→ 用户一键确认或回滚。

**不是**：用户输入 → 系统说"已执行" → 用户也不知道发生了什么。

### 1.2 核心交互流

```
用户输入: "清理 /var/log 下 30 天前的日志"
    │
    ▼
┌─────────────────────────────────────────────┐
│ 系统响应（3 秒内）:                          │
│                                             │
│ 🔍 预分析:                                   │
│   - 将影响 /var/log (1.2 GB, 847 个文件)     │
│   - 风险评估: ⚠️ 中风险 (可逆操作)            │
│   - 建议: 先 tar 备份到 /backup/logs         │
│                                             │
│ 🛡️ 沙箱保护:                                 │
│   - 写时复制模式 (原始文件不变)               │
│   - 已限制: CPU 30s, 内存 512MB              │
│   - 系统调用: 允许 67 个, 拦截 143 个         │
│                                             │
│ [预演] [确认执行] [取消]                      │
└─────────────────────────────────────────────┘
    │ (用户点「确认执行」)
    ▼
┌─────────────────────────────────────────────┐
│ 执行结果: ✅ 成功 (耗时 2.3s)                 │
│                                             │
│ 📝 文件变更:                                  │
│   删除: 823 个 .log 文件                      │
│   释放: 1.1 GB                               │
│   ✅ 未触及: /var/log/audit, /var/log/secure │
│                                             │
│ 🔙 回滚: 可回滚 (写时复制快照保留 72h)        │
│                                             │
│ [保留变更] [回滚] [查看变更详情]              │
└─────────────────────────────────────────────┘
```

### 1.3 体感差异

| 维度 | 当前体验 | 目标体验 |
|------|---------|---------|
| 执行前 | 无预演 | 自动展示影响范围 + 风险评估 |
| 执行中 | 无感知 | 实时显示隔离层数 + 资源使用 |
| 执行后 | 只有 stdout | 变更清单 + diff 详情 + 一键回滚 |
| 安全感 | "应该没问题" | "我知道它做了什么保护" |

### 1.4 接口契约（从体验倒推）

```python
# 用户视角：一个 execute() 就够了
class SandboxSession:
    """一次沙箱会话 = 用户的"一次操作" """
    
    # --- 用户看到的第一屏 ---
    def preview(self, command: str) -> PreviewCard:
        """预分析结果 — 用户决定「要不要执行」的依据"""
        # 返回: {影响范围, 风险等级, 防护措施, 建议替代方案}
    
    # --- 用户执行 ---
    def execute(self, command: str, confirmed: bool) -> ExecutionCard:
        """执行 — 带实时状态"""
        # 返回: {成功/失败, 耗时, 隔离层数, 资源使用}
    
    # --- 用户看结果 ---
    def changes(self) -> ChangeReport:
        """执行后的文件变更清单 — 用户决定「要不要回滚」的依据"""
        # 返回: {新增/修改/删除文件列表, diff 摘要, 可回滚?}
    
    def rollback(self) -> RollbackResult:
        """一键回滚"""
    
    def commit(self) -> CommitResult:
        """确认变更，写时复制层合并到真实文件系统"""
```

## 二、终端智能 — 体验设计

### 2.1 目标体验

> 用户不需要记住精确命令。描述意图 → 系统建议命令 → 预演 → 确认 → 执行 → 学习。

**不是**：用户输命令 → 系统跑命令 → 下次用户还得自己记住命令。

### 2.2 核心交互流

```
用户: "看看哪个进程在大量写磁盘"
    │
    ▼
┌─────────────────────────────────────────────┐
│ 🤖 理解意图: 磁盘IO排查                       │
│                                             │
│ 💡 建议命令:                                  │
│   iotop -bon1 | head -20                     │
│   (观测类 · 安全 · 2 秒前你用过类似命令)       │
│                                             │
│ 📊 历史: 你上周用过 iotop 3 次, 成功率 100%    │
│                                             │
│ [直接执行] [修改命令] [看其他方案]             │
└─────────────────────────────────────────────┘
    │ (用户点「直接执行」)
    ▼
┌─────────────────────────────────────────────┐
│ ✅ 执行完成 (0.8s)                           │
│                                             │
│ 进程 mysql (PID 1234): 45 MB/s 写入          │
│ 进程 backup (PID 5678): 12 MB/s 写入         │
│                                             │
│ 🧠 已记住: "查磁盘IO" → iotop -bon1           │
│                                             │
│ [查看详情] [这个结果有问题?]                   │
└─────────────────────────────────────────────┘
```

### 2.3 体感差异

| 维度 | 当前体验 | 目标体验 |
|------|---------|---------|
| 输入 | 必须精确命令 | 自然语言意图即可 |
| 学习 | 无 | 记住成功模式，下次秒级建议 |
| 信任 | 不知道靠不靠谱 | 展示历史成功率 + 相似案例 |
| 纠错 | 错了自己查 | 系统检测异常并主动提示 |

### 2.4 接口契约

```python
class IntelligentTerminal:
    """用户视角的智能终端"""
    
    def understand(self, intent: str) -> IntentAnalysis:
        """理解用户意图 → 返回分析结果 + 建议命令"""
        # 返回: {意图分类, 建议命令(1-3个), 每个命令的风险/历史成功率}
    
    def execute(self, command: str, context: TerminalContext) -> ExecResult:
        """执行命令（连接沙箱）"""
        # 返回: {结果, 文件变更, 副作用检测, 本次学习摘要}
    
    def verify(self, result: ExecResult) -> VerifyVerdict:
        """执行后验证 — 结果看起来正常吗?"""
        # 返回: {通过/存疑/异常, 存疑原因, 建议的下一步}
    
    def learn(self, intent: str, command: str, result: ExecResult):
        """学习 — 用户不会感知到这一步，系统自动完成"""
```

## 三、告警系统 — 体验设计

### 3.1 目标体验

> 安静的时候就是没事。有事的时候，**精准、不重复、能解释**。

**不是**：每 5 秒弹一条，用户麻木了把整个告警关了。

### 3.2 告警分级体验

```
告警量
  │
  │  ████████████  ← 当前: 所有事件都写日志，严重/高还弹窗
  │  ████████████     用户体感: "又是告警，关了关了"
  │
  ▼
  │  ░░░░░░       ← 目标: 日常很安静
  │  ░░██░░       ← 偶尔有聚合摘要(Toast, 3秒消失)
  │  ░░██░░       
  │  ██▓▓██       ← 真正需要关注的才弹横幅
  │  ░░██░░       
  │  ░░░░░░       
  └──────────────────→ 时间
```

### 3.3 浮屏体感矩阵

```
                    频率低              频率高
             ┌─────────────────┬─────────────────┐
    严重     │ 桌面通知 + 横幅   │ 模态框提醒       │
   (P0/P1)  │ "磁盘即将爆满"    │ "5台主机同时异常" │
             ├─────────────────┼─────────────────┤
    中等     │ 侧栏角标 +1      │ Toast 摘要       │
   (P2/P3)  │ 用户自己决定看    │ "过去1h: 3条告警" │
             ├─────────────────┼─────────────────┤
    信息     │ 只写日志          │ 聚合为统计数字    │
   (info)   │ 用户不需要感知    │ "今日: 42条正常"  │
             └─────────────────┴─────────────────┘
```

### 3.4 核心交互流

```
场景A: 磁盘使用率达到 92%（P1）
    │
    ▼
┌─────────────────────────────────────────────┐
│ 🟡 磁盘空间告警                               │
│ /dev/sda1 使用率 92% (剩余 8.3 GB)            │
│ 趋势: 过去 6 小时增长 3% → 预计 14 小时后满   │
│                                             │
│ 🔧 建议: 运行自动清理 (可释放 ~2.1 GB)        │
│                                             │
│ [自动清理] [查看详情] [暂时忽略(1h后再提醒)]    │
└─────────────────────────────────────────────┘

场景B: 同一告警重复出现 5 次
    │
    ▼
    系统自动合并: "磁盘告警 (×5)" → 只通知一次
    如果用户点了「暂时忽略」→ 1h 内同类型告警不重复通知

场景C: 告警持续 30 分钟未处理
    │
    ▼
    自动升级: P1 → P0，通知方式从 Toast → 横幅
```

### 3.5 接口契约

```python
class AlertExperience:
    """告警体验控制器 — 决定「用户看到什么」"""
    
    def decide(self, event: RawEvent, context: AlertContext) -> AlertAction:
        """一个事件要不要让用户知道？以什么形式？
        
        Returns:
            silent    — 只记日志，不打扰
            badge     — 侧栏角标 +1
            toast     — 右下角浮窗，3秒消失
            banner    — 顶部横幅，需手动关闭
            modal     — 模态框，必须响应
        """
    
    def aggregate(self, window_minutes: int = 5) -> AlertSummary:
        """聚合最近告警 — 用户看的不是单条，是摘要"""
        # 返回: {按类型分组, 按主机分组, 根因推测, 趋势}
    
    def escalate(self, alert_id: str) -> AlertAction:
        """告警升级 — 超过阈值未处理 → 提高通知级别"""
```

## 四、文档智能 — 体验设计

### 4.1 目标体验

> 系统**持续消化文档**，用户遇到问题时，系统**主动关联**相关文档片段，处置完成后**自动沉淀**为新知识。

**不是**：30 条硬编码 Playbook，用户得自己搜。

### 4.2 核心交互流

```
场景: 用户问 "nginx 502 怎么办"
    │
    ▼
┌─────────────────────────────────────────────┐
│ 📚 相关知识 (3 条)                            │
│                                             │
│ ✅ 高度匹配:                                  │
│   PB-WEB-03 · Nginx 502 排查流程              │
│   匹配度: 94% · 上次生效: 2 天前              │
│   "先查 upstream 状态 → 再查 error.log →     │
│    最后查连接数"                              │
│                                             │
│ ⚡ 最近案例:                                  │
│   2026-07-10 · 生产环境 Nginx 502             │
│   根因: php-fpm socket 满了                  │
│   处置: 调大 backlog + 重启 php-fpm           │
│   → 一键复用此处置方案                        │
│                                             │
│ 📖 参考文档:                                  │
│   /etc/nginx/nginx.conf · 第 32-45 行        │
│                                             │
│ [执行建议方案] [查看完整 Playbook] [自己处理]   │
└─────────────────────────────────────────────┘
```

### 4.3 体感差异

| 维度 | 当前体验 | 目标体验 |
|------|---------|---------|
| 知识来源 | 30 条硬编码 | 文档自动解析 + 案例自动沉淀 |
| 检索方式 | 关键词匹配 | 语义理解 + 上下文关联 |
| 知识保鲜 | 手动更新代码 | 自动检测过时 + 标记新鲜度 |
| 学习闭环 | 无 | 处置结果反哺知识库 |

### 4.4 接口契约

```python
class DocumentExperience:
    """文档智能体验 — 让知识「活」起来"""
    
    def ingest(self, source: DocumentSource) -> IngestResult:
        """吃进一份文档 → 自动解析、分块、索引"""
    
    def query(self, question: str, context: dict) -> KnowledgeResponse:
        """用户提问 → 相关文档片段 + 匹配度 + 案例"""
    
    def learn_from_incident(self, incident: IncidentReport) -> KnowledgeDelta:
        """从处置案例中自动抽取知识点 → 草稿 → 待审核"""
    
    def freshness_report(self) -> FreshnessReport:
        """知识健康报告 — 哪些 Playbook 可能过时了？"""
```

## 五、边界韧性 — 体验设计

**不是**：几根静态探针跑一跑，没发现问题就觉得自己安全。

系统后台 (每天凌晨 2:00 自动运行):

```python
class BoundaryExperience:
    """边界韧性体验 — 系统的「免疫系统」"""
    
    def daily_patrol(self) -> PatrolReport:

    def trend(self, days: int = 30) -> SecurityTrend:
        """安全态势趋势 — 越来越安全还是越来越脆弱？"""
```

## 六、模块间交互契约

### 6.1 事件流（用户执行一条命令的全链路）

```
User.intent("清理旧日志")
    │
    ▼
IntelligentTerminal.understand()
    │ 返回: IntentAnalysis { 建议命令, 风险, 历史成功率 }
    │
    ▼
SandboxSession.preview(command)
    │ 返回: PreviewCard { 影响范围, 防护层数, 风险等级 }
    │
    ▼ (用户确认)
SandboxSession.execute(command)
    │ 内部: OverlayFS 挂载 → seccomp 加载 → namespace 隔离
    │ 返回: ExecutionCard { 成功, 耗时, 资源使用 }
    │
    ▼
SandboxSession.changes()
    │ 返回: ChangeReport { 新增/修改/删除, diff }
    │
    ▼
IntelligentTerminal.verify(result)
    │ 返回: VerifyVerdict { 通过/存疑, 原因 }
    │
    ▼
IntelligentTerminal.learn(intent, command, result)
    │ 静默: 更新命令模板库 + 调整风险模型
    │
    ▼
DocumentExperience.learn_from_incident(incident)
    │ 静默: 自动抽取知识 → 待审核草稿
    │
    ▼ (如果触发了告警条件)
AlertExperience.decide(event, context)
    │ 返回: AlertAction { silent/badge/toast/banner/modal }
```

### 6.2 数据流（模块间传递的核心结构）

```
IntentAnalysis  ← IntelligentTerminal 产出 → SandboxSession 消费
PreviewCard     ← SandboxSession 产出   → 前端展示
ChangeReport    ← SandboxSession 产出   → FileVersionManager 消费
VerifyVerdict   ← IntelligentTerminal 产出 → AlertExperience 消费
KnowledgeDelta  ← DocumentExperience 产出 → KnowledgeGuard 消费
PatrolReport    ← BoundaryExperience 产出 → AlertExperience 消费
```

## 七、执行顺序（体验驱动）

先做用户**感知最强**的，再做后台静默的。

```
Step 1: SandboxSession.preview() + execute() + changes()
         ↓ 用户立刻感受到 "执行命令变得透明了"
         
Step 2: AlertExperience.decide() + aggregate()
         ↓ 用户立刻感受到 "告警变少了，但重要的更清楚了"
         
Step 3: IntelligentTerminal.understand() + learn()
         ↓ 用户立刻感受到 "终端懂我了"
         
Step 4: DocumentExperience.query() + learn_from_incident()
         ↓ 用户立刻感受到 "知识库活了"
         
Step 5: BoundaryExperience.daily_patrol() + challenge()
         ↓ 安全工程师感受到 "系统在自我进化"
         
Step 6: KnowledgeGuard.check_consistency() + freshness_report()
         ↓ 知识库管理员感受到 "知识不会腐烂"
```

## 八、每个 Step 的体验验收标准

### Step 1: 沙箱体验上线

- [ ] 用户执行任意命令后，能看到 **文件变更清单**（不是只有 stdout）
- [ ] 用户执行高风险命令前，看到 **预分析卡片**（影响范围 + 风险等级）
- [ ] 用户可以在执行后 **一键回滚** 文件变更
- [ ] 回滚时间 < 1 秒（写时复制，不是 cp 恢复）

### Step 2: 告警体验上线

- [ ] 同一告警 5 分钟内不会重复弹窗
- [ ] 低优先级告警不弹窗（只记日志 + 角标）
- [ ] 用户点「暂时忽略」后，1 小时内同类型不再打扰
- [ ] 累计告警超过阈值时，显示聚合摘要而非刷屏

### Step 3: 终端体验上线

- [ ] 用户输入自然语言意图 → 系统给出 1-3 个命令建议
